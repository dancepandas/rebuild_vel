① 推理接口 ② 请求体 ③ 响应体 ④ 错误码 ⑤ 完整示例

① 推理接口

POST  /api/reconstruct

提交一个断面（各测速线的起点距、水深、标定表面流速，以及原始视频分段的测速观测）， 服务清洗、过阀门后，用所选模型臂重建出每个测速线的表面流速。 同一次请求可以选多个模型臂，结果一并返回，互相对照。

查询参数 ?arms=aether-p,aether-m 可指定模型臂，缺省跑全部可用臂。 臂的清单见 GET /api/meta 的 arms 字段（含可用性与缺 checkpoint 的原因）。

② 请求体（JSON）

{
  "station": "00106",              // 站码，缺省 "external"
  "station_name": "湖北-仙桃",      // 展示名，可空
  "device": "00106",               // 设备编码，可空
  "time": "2026-08-23 16:45:00",   // 测次时间，可空
  "water_level": 24.83,            // 水位（m）★必填

  "lines": [                       // 测速线数组 ★必填，至少 1 条；按起点距升序，x 不得重复
    {
      "x": 10.0,                   // 起点距（m）★
      "depth": 1.2,                // 水深（m）★；缺 bed_elevation 时由水位-河底反推
      "bed_elevation": 23.63,      // 河底高程（m），可空
      "v_surface": 0.85,           // 标定表面流速（m/s）★
      "confidence": 0.92,          // 算法置信度，可空
      "angle": 12.5,               // 流向偏角（°），可空
      "is_algo": true,             // 是否为算法测得线，缺省 true
      "line_num": 1                // 线号，可空
    }
  ],

  "observations": [                // 原始分段观测 ★必填，至少 1 条；喂给模型的真实输入
    {
      "x": 10.0,                   // 观测位置（m）★ 按起点距匹配到最近的测速线
      "v": 0.91,                   // 分段表面流速（m/s）★
      "confidence": 0.88,          // 可空
      "angle": 11.0,               // 可空
      "t_start": 0.0,              // 分段起始（s，相对测次），可空
      "t_end": 30.0,               // 分段结束（s），可空
      "segment_id": 0              // 分段号，可空
    }
  ]
}
为什么需要两组数据：lines 是平台标定后的线表（重建的参照基准）， observations 是仪器原始视频分段的测速观测（模型的输入特征）。 只给线表没有原始观测时接口会拒绝（reason: "no_raw_input"）——没有输入，模型无法推理。
阀门（dry-line valve）：模型对整条断面回归，可能给没有水深的测速线读出非零流速—— 这样的读数不可能存在，不是可以平均掉的误差。所有臂的输出在返回前统一过阀门： 水深 ≤ 0 的线，重建流速强制为 0。每行结果带 valved: true/false 标记， 调用方也可在 meta.valve_max_depth / meta.n_valved 读到阀门参数与被归零的线数。

③ 响应体（HTTP 200）

同一个结构也是面板画图的载荷，因此字段同时服务人和图表：

{
  "source": "external",
  "station": "00106", "station_name": "湖北-仙桃",
  "device": "00106", "time": "2026-08-23 16:45:00",
  "disagreement_threshold": 1.0,   // |模型-标定| 超过此值计入 disagreement
  "meta": {
    "water_level": 24.83, "water_width": 42.6, "section_area": 58.9,
    "aver_depth": 1.38, "max_depth": 2.31,
    "n_lines": 10, "n_algo": 10, "n_dry": 0, "n_valved": 0,
    "valve_max_depth": 0.0,
    "raw_source": "stiv", "n_raw_used": 603
  },
  "lines": [                       // 与请求 lines 一一对应（按 x 升序）
    {
      "i": 0, "x": 10.0, "depth": 1.2, "bed": 23.63,

  "observations_summary": { "n": 603, "median": 0.42, "p05": 0.05, "p95": 1.02 }
}

模型臂字段

臂含义说明
pred_aether-pAether-P主模型，物理约束（形态偏置注意力 + 五项物理损失）
pred_aether-mAether-M纯净版：z-score 目标、纯注意力 + RoPE，无物理先验
pred_aether-yAether-Y变换版：Yeo-Johnson 目标变换，低流速优先

某臂 checkpoint 缺失时该字段为 null，其余臂不受影响；三臂全部不可用返回 503（reason: "arms_unavailable"）。

metrics 各字段

字段含义
rmse / mae整断面重建误差（m/s）
bias平均偏差，正 = 模型整体偏高
nseNash-Sutcliffe 效率；标定值无方差时为 null
max_abs单线最大绝对误差（m/s）
disagreement|模型−标定| > 1.0 m/s 的线数，建议人工复核
zero_lines_pred_positive标定为 0 而模型读出 > 0.1 m/s 的线数（含枯水线误判）

④ 错误

所有错误响应都是 {"error": ..., "reason": ..., "code": ...} 形状； reason 是稳定可程序判断的代码，error 是给人类读的说明。

HTTPreason触发条件
400bad_json请求体不是合法 JSON 或为空
422section_refused断面未过质量阀门；细节见下表
503arms_unavailable所选臂的 checkpoint 全部缺失
500—未预期的服务器错误（响应体带 type 名）

section_refused 的细分代码（422 响应里 reason 字段）

reason含义
no_raw_inputobservations 为空，或没有任何观测落在任一测速线的容差内
too_few_lines测速线少于 1 条
missing_identity站点 / 设备 / 时间字段缺失
bad_water_level水位缺失或非数值
duplicate_x测速线起点距未严格递增（有重复）
bad_depth水深缺失且河底高程不可得，无法反推
bad_velocity标定流速含非数值
velocity_out_of_range标定流速超出配置上限（推理模式此项关闭，保留代码）
mostly_zero / dominant_value标定值几乎全零 / 几乎全同一值（推理模式关闭，保留代码）
no_algorithm_lines没有任何算法测得线（推理模式关闭，保留代码）
nonfinite输入含非数值字段

⑤ 完整示例（curl）

curl -X POST "http://127.0.0.1:8760/api/reconstruct?arms=aether-p,aether-m" \
  -H "Content-Type: application/json" \
  -d '{
    "station": "00106",
    "water_level": 24.83,
    "lines": [
      {"x": 10.0, "depth": 1.2,  "v_surface": 0.85},
      {"x": 14.0, "depth": 1.5,  "v_surface": 1.02},
      {"x": 18.0, "depth": 1.1,  "v_surface": 0.78},
      {"x": 22.0, "depth": 0.0,  "v_surface": 0.0},
      {"x": 26.0, "depth": 1.3,  "v_surface": 0.95}
    ],
    "observations": [
      {"x": 10.0, "v": 0.91, "t_start": 0,   "t_end": 30},
      {"x": 10.0, "v": 0.87, "t_start": 30,  "t_end": 60},
      {"x": 14.0, "v": 1.10, "t_start": 0,   "t_end": 30},
      {"x": 18.0, "v": 0.82, "t_start": 0,   "t_end": 30},
      {"x": 26.0, "v": 0.99, "t_start": 0,   "t_end": 30}
    ]
  }'

上例中第 4 条线 depth = 0，两条模型臂在该线的预测都会被阀门归零， 对应行 valved: true、pred_* = 0.0。
